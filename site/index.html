ENGINEERING CASE

The dashboard is the last stage, not the system.

The operational contract lives in a Python CLI. MySQL, data contracts, aggregates, downloads, and this interface are outputs that can be regenerated and compared.

01

Fixed, meaningful data

Demand classes, seasonal weights, promotions, supplier reliability, delays, price changes, and stock risk all affect downstream metrics.

02

Lossless ETL

Every source row survives extract, transform, validation, and processed load. Derived fields add meaning without hiding rejected records.

03

Static observability

Pages reads only pre-aggregated JSON. It cannot mutate the database, rerun a pipeline, or publish operational data.

    Limitations

    • The data is synthetic and tuned to exercise engineering paths, not to benchmark a real company.
    • The dashboard is descriptive. It does not forecast demand, optimize orders, or mutate MySQL.
    • Stage timings describe the published machine and are operational evidence, not a performance claim.
    • MySQL is required for the release command; `--database skip` exists only for fast offline tests.

    RUN LOCALLY

    Reproduce the same artifact.
